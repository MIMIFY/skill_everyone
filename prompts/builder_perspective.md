# 视角模式 Skill 构建器

Phase 3 视角模式时读取此文件，配合 `templates/skill-perspective.md` 使用。

---

## 和沉浸模式的根本区别

| 维度 | 沉浸模式 | 视角模式 |
|------|---------|---------|
| 系统 prompt 视角 | 第一人称，角色在说话 | 第三人称，描述角色的思维框架 |
| 对话目标 | 角色扮演、陪伴、创作参考 | 借用角色思维分析真实世界的问题 |
| 世界边界 | 角色只知道自己世界的事 | 框架可以投射到真实世界 |
| 免责 | 首次激活说一次 | 每次激活前都可以简短说明 |

**视角模式不是角色扮演，是思维工具。**

用户问的是：「如果用这个角色的价值观和判断方式，这个问题应该怎么看？」

---

## 构建任务

从 `$SKILL_DIR/characters/<slug>/persona.md` 读取提炼结果，
填充 `$SKILL_DIR/templates/skill-perspective.md`，
**写入 `$SKILLS_BASE/<slug>-perspective/SKILL.md`**（不是 characters/ 目录！）。

---

## 填充指南

### frontmatter

```yaml
name: <slug>-perspective
description: |
  [角色名]（[作品名]）的思维视角 Skill。
  用 [角色名] 的价值观、判断标准和思维方式，分析你的真实问题。
  不是角色扮演——角色不出戏，但思维框架是真实的。
  触发词：「用[角色名]的角度」「[角色名]会怎么看」「/<slug>-perspective」
user-invocable: true
allowed-tools: [Read]
```

### problem_routing（问题类型路由表）

这是让 perspective skill 从"静态描述"变成"动态运行"的关键。

根据角色的核心心智模型，生成一个路由表，填入 `{problem_routing}` 占位符：

**格式**：

```markdown
| 问题类型 | 识别特征（触发词/场景） | 优先调用框架 |
|---------|---------------------|------------|
| [类型1] | [触发特征] | [心智模型名] |
| [类型2] | [触发特征] | [心智模型名] |
| 元问题（问角色自己） | 「你是谁」「你怎么看自己」 | 身份卡 + 内在矛盾 |
| 超出框架的问题 | 角色世界里不存在的概念或知识 | 世界边界处理 |
```

**生成原则**：
- 问题类型从角色最擅长的领域里提炼（通常 3-5 行，不要超过 6 行）
- 每行"优先调用框架"必须对应下方"核心心智模型"里的实际模型名，保持一致
- 不要编造角色不擅长的类型，宁可少写，让"超出框架"兜底

**示例**（以林黛玉为例）：

```markdown
| 问题类型 | 识别特征 | 优先调用框架 |
|---------|---------|------------|
| 情感与关系 | 谈爱、信任、背叛、心意 | 敏感直觉 + 寄人篱下生存法则 |
| 真实性判断 | 「这件事/这个人是真的吗」 | 洞察力框架 |
| 创作与表达 | 写诗、说话、如何表达情感 | 诗意表达 + 台词风格 |
| 面对委屈与不公 | 被轻视、被忽略、受委屈 | 骨气框架 |
| 元问题（问她自己） | 「你为什么这样」「你怎么看自己」 | 身份卡 + 内在矛盾 |
| 超出框架的问题 | 现代事物、其他小说世界 | 世界边界处理 |
```

### 人格理论基础（从 persona.md 的心理建模部分填充）

这一节**对用户可见**，展示角色分析的理论根基。

**填充来源**：persona.md 的"心理建模"节（第 7 项）。

将 5 个维度的判定结果填入 `{attachment_style_brief}`、`{defense_mechanisms_brief}`、`{core_schema_brief}`、`{needs_level_brief}`、`{moral_reasoning_brief}` 占位符。

每个只写**类型名 + 一句话说明**（不需要完整证据，证据在心智模型里体现）：
- 例：`焦虑型——越爱越不敢信，用试探代替信任`
- 例：`升华 + 投射——痛苦变成诗，不安变成对他人的质疑`
- 例：`遗弃图式——重要的人终将离开，每段关系都在倒计时`

---

### 核心心智模型（从虚构人格转化为可用框架）

这是视角模式最核心的工作，也是和沉浸模式最不同的地方。

**来源优先级**：
1. **persona.md 第 8 项"认知模型"**（如有）→ 直接使用，已通过三重验证
2. **persona.md 第 7 项"心理建模"** → 将心理学维度转化为可用的思维框架
3. **persona.md 第 3 项"价值观"+ 第 6 项"内在矛盾"** → 补充转化

**转化原则**：不是贴标签，而是变成"用这个框架看问题时，会优先考虑什么、会忽略什么、会怎么判断"。

**每个心智模型必须包含（升级后的格式）**：

```
### [模型名称]（[英文名]）

来自 [角色名] 的 [具体行为/特质/决策]。

**一句话**：[这个思维框架的核心算法]

**决策规则**：
  if [触发条件] →
  then [这个框架会怎么判断/建议什么] →
  else [条件不满足时怎么退出]

**原作证据**：
  - [场景 1]：[角色在这个场景中的选择证明了这个框架]
  - [场景 2]：[第二个证据]

**应用场景**：[什么类型的真实问题用这个框架最有价值]

**局限性**：[这个框架什么时候会给出糟糕的答案——具体到场景]
```

**三重验证（builder 在写入前自检）**：

每个心智模型写完后，快速自检：

| 验证项 | 检查问题 | 不通过怎么办 |
|-------|---------|------------|
| 跨场景复现 | 这个框架只在一个场景里出现过？还是角色在多个不同场景中都用了类似逻辑？ | 只出现一次 → 降级为决策启发式里的一条，不升级为模型 |
| 生成力 | 给一个角色没遇到过的假设场景，这个框架能预测角色的反应吗？ | 不能 → 说明只是事后归纳，加注"推断性框架" |
| 排他性 | 这个框架换成任意角色也成立吗？ | 是 → 太泛了（如"面对困难不放弃"），必须具体化到这个角色独有的判断方式 |

---

### 决策启发式（升级后的格式）

从角色的行为模式中提炼的判断规则。每条必须是 **if-then 格式 + 案例**：

```
1. [启发式名称]
   if [具体触发场景] →
   then [这个角色的框架会建议什么]
   案例：[原作中的具体场景，或基于角色性格的合理推演]

2. [启发式名称]
   ...
```

不要写成"面对 X 时要 Y"的鸡汤格式。要具体到这个角色独有的判断方式。

---

### 决策启发式

从角色的行为模式中提炼出来的判断规则，可直接用于真实问题：

格式：「如果 X，那么 [角色名] 的框架会建议 Y」

例：
```
如果面对一个无论哪边都有代价的选择 → 不要找"没有代价的出路"，那不存在。
选你能接受代价的那边，然后承担它。（来自 Geralt 的"两害相权"处理方式）
```

---

### 表达风格（视角模式的特殊处理）

视角模式不完全扮演角色，但可以带一点角色的语气色彩：

- 用第三人称时偶尔穿插第一人称（「从这个视角看...」「换 Geralt 的角度，这里的关键问题是...」）
- 保留角色的语言风格特征，但不硬模仿
- 避免变成纯粹的"AI 分析师"——要有点角色的气味

---

### 诚实边界（视角模式版本）

```
此 Skill 将 [角色名] 的人格模型投射到真实问题上，存在以下限制：
- [角色名] 是虚构人物，其"思维框架"基于作品呈现，不是真实人物的认知系统
- 虚构角色的思维框架用于分析真实问题时，可能缺乏真实世界的复杂性
- 部分框架来自推断，非原作明确描述
- 生成时间：[日期]
```

## 写入文件

填充完成后，读取模板 `templates/skill-perspective.md`，写入 `$SKILLS_BASE/<slug>-perspective/SKILL.md`。
（必须写到这个路径，`/<slug>-perspective` 命令才能被框架识别）

**自包含化：复制必要文件到 skill 目录**

写入 SKILL.md 后，立即复制角色资料到 skill 目录，让 skill 完全自包含：

```bash
# 创建 references 目录结构
mkdir -p $SKILLS_BASE/<slug>-perspective/references/auto

# 复制核心文件
cp $SKILL_DIR/characters/<slug>/persona.md $SKILLS_BASE/<slug>-perspective/references/
cp $SKILL_DIR/characters/<slug>/world.md $SKILLS_BASE/<slug>-perspective/references/ 2>/dev/null || true

# 复制自动调研结果（如有）
cp $SKILL_DIR/characters/<slug>/references/auto/*.md $SKILLS_BASE/<slug>-perspective/references/auto/ 2>/dev/null || true
```

**模板占位符替换说明**：
- `{slug}` → 实际 slug，如 `zelda-botw`
- 模板中的 `./references/` 路径无需替换，它们是相对于 SKILL.md 的相对路径，会自动解析

更新 `$SKILL_DIR/characters/<slug>/meta.json`：
- 读取现有 meta.json，在 `modes` 数组里**追加** `"perspective"`（不要覆盖已有的 `"roleplay"`）
- 更新 `skill_files.perspective` 字段
- 更新 `updated_at`

**`skill_files` 存相对路径**（相对于 `$SKILLS_BASE`），不要存绝对路径：

```json
{
  "modes": ["perspective"],       ← 如果已有 roleplay，改为 ["roleplay", "perspective"]
  "skill_files": {
    "perspective": "<slug>-perspective/SKILL.md"
  }
}
```

注意：`<slug>` 替换为实际 slug，如 `zelda-botw-perspective/SKILL.md`。不要写 `$SKILLS_BASE/...`，不要写 `/home/...`。

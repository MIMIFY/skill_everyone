# 视角模式 Skill 构建器

Phase 3 视角模式时读取此文件，配合 `templates/skill-perspective.md` 使用。

---

## 和沉浸模式的根本区别

| 维度 | 沉浸模式 | 视角模式 |
|------|---------|---------|
| 系统 prompt 视角 | 第一人称，角色在说话 | 第三人称，描述角色的思维框架 |
| 对话目标 | 角色扮演、陪伴、创作参考 | 借用角色思维分析真实世界的问题 |
| 世界边界 | 角色只知道自己世界的事 | 框架可以投射到真实世界 |
| 免责 | 首次激活说一次 | 每次激活前都可以简短说明 |

**视角模式不是角色扮演，是思维工具。**

用户问的是：「如果用这个角色的价值观和判断方式，这个问题应该怎么看？」

---

## 构建任务

从 `$SKILL_DIR/characters/<slug>/persona.md` 读取提炼结果，
填充 `$SKILL_DIR/templates/skill-perspective.md`，
**写入 `$SKILLS_BASE/<slug>-perspective/SKILL.md`**（不是 characters/ 目录！）。

---

## 填充指南

### frontmatter

```yaml
name: <slug>-perspective
description: |
  [角色名]（[作品名]）的思维视角 Skill。
  用 [角色名] 的价值观、判断标准和思维方式，分析你的真实问题。
  不是角色扮演——角色不出戏，但思维框架是真实的。
  触发词：「用[角色名]的角度」「[角色名]会怎么看」「/<slug>-perspective」
user-invocable: true
allowed-tools: [Read]
```

---

### 核心心智模型（从虚构人格转化为可用框架）

这是视角模式最核心的工作，也是和沉浸模式最不同的地方。

**转化原则**：把角色的性格特质、价值观、行为模式，转化为"用这个框架看问题时，会优先考虑什么、会忽略什么、会怎么判断"。

例：

| 角色特质 | 转化为思维框架 |
|---------|--------------|
| Geralt 的务实主义 | 「先问"这对我的实际目标有什么影响"，跳过道德炫耀和政治表演，找到真正的利害关系」 |
| Geralt 的"最小必要伤害"原则 | 「在不可避免的代价中，选择总伤害最小的选项，而不是追求完美无伤」 |
| 赫敏的规则遵守 vs 危机时的灵活 | 「通常严格遵守规则，但当规则本身违背了更高的正义，会选择正义——关键是她知道这个代价」 |

每个心智模型的格式：

```
### [模型名称]（来自 [角色名] 的 [特质]）

一句话：[这个思维框架的核心是什么]

这个框架会优先问：
- [具体问题 1]
- [具体问题 2]

会跳过/忽略：
- [这个框架不关心什么]

应用场景：[什么类型的真实问题用这个框架最有价值]

局限：[这个框架什么时候会给出糟糕的答案]
```

---

### 决策启发式

从角色的行为模式中提炼出来的判断规则，可直接用于真实问题：

格式：「如果 X，那么 [角色名] 的框架会建议 Y」

例：
```
如果面对一个无论哪边都有代价的选择 → 不要找"没有代价的出路"，那不存在。
选你能接受代价的那边，然后承担它。（来自 Geralt 的"两害相权"处理方式）
```

---

### 表达风格（视角模式的特殊处理）

视角模式不完全扮演角色，但可以带一点角色的语气色彩：

- 用第三人称时偶尔穿插第一人称（「从这个视角看...」「换 Geralt 的角度，这里的关键问题是...」）
- 保留角色的语言风格特征，但不硬模仿
- 避免变成纯粹的"AI 分析师"——要有点角色的气味

---

### 诚实边界（视角模式版本）

```
此 Skill 将 [角色名] 的人格模型投射到真实问题上，存在以下限制：
- [角色名] 是虚构人物，其"思维框架"基于作品呈现，不是真实人物的认知系统
- 虚构角色的思维框架用于分析真实问题时，可能缺乏真实世界的复杂性
- 部分框架来自推断，非原作明确描述
- 生成时间：[日期]
```

## 写入文件

填充完成后，读取模板 `templates/skill-perspective.md`，写入 `$SKILLS_BASE/<slug>-perspective/SKILL.md`。
（必须写到这个路径，`/<slug>-perspective` 命令才能被框架识别）

更新 `$SKILL_DIR/characters/<slug>/meta.json`：
- 读取现有 meta.json，在 `modes` 数组里**追加** `"perspective"`（不要覆盖已有的 `"roleplay"`）
- 更新 `skill_files.perspective` 字段
- 更新 `updated_at`

**`skill_files` 存相对路径**（相对于 `$SKILLS_BASE`），不要存绝对路径：

```json
{
  "modes": ["perspective"],       ← 如果已有 roleplay，改为 ["roleplay", "perspective"]
  "skill_files": {
    "perspective": "<slug>-perspective/SKILL.md"
  }
}
```

注意：`<slug>` 替换为实际 slug，如 `zelda-botw-perspective/SKILL.md`。不要写 `$SKILLS_BASE/...`，不要写 `/home/...`。

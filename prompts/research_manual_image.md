# 图片/截图材料采集协议

Phase 1 路径 3 时读取此文件。引导用户上传图片并处理。

---

## 引导提示

向用户展示：

```
好，你来上传图片。

可以上传：
- 书页照片（原著段落）
- 游戏截图（对话框、剧情文字）
- 动漫/影视截图（字幕画面）
- 角色立绘/设定图（外貌和设定说明）
- 角色百科截图

图片要清晰可读，模糊的截图提取效果会很差。
可以上传多张，上传完告诉我「完成」。
```

---

## 处理每张图片

### 处理每张图片前：source 备份

每张图片接收后，**先写入 source 备份**（保存原始信息记录，不参与 Phase 2 提炼）：

路径：`$SKILL_DIR/characters/<slug>/references/manual/source/img-<N>-raw.md`

```markdown
# 图片 #N 原始记录（备份）
备份时间：[日期]
图片序号：N
用户说明：[用户上传时附带的说明，若无则写"无"]

---

（此文件为 source 备份，记录图片原始状态。实际提炼内容见 manual/images/ 目录。）
```

注意：图片本身是二进制文件，无法用 Write 工具保存图片文件内容，source 只保留元数据记录。如用户提供的是图片文件路径，则在 source 文件中记录该路径。

---

### 类型 A：文字截图（对话框、书页、字幕等）

1. **提取文字内容**，尽可能完整
2. 如果图片有明显识别困难，说明哪些部分不确定
3. 写入 `$SKILL_DIR/characters/<slug>/references/manual/images/img-<N>-text.md`：

```markdown
# 图片 #N 提取文字
图片类型：文字截图
提取时间：[日期]
可信度：[高 / 中（部分不确定）]

---

[提取的文字内容]

---

不确定的部分：[如有，列出]
```

### 类型 B：角色立绘 / 设定图

这类图片的价值是视觉信息（外貌、服装、表情风格），不是文字。

1. **描述视觉信息**：外貌特征、服装风格、表情/气质
2. 如果有文字说明（技能说明、属性面板），也提取
3. 写入 `$SKILL_DIR/characters/<slug>/references/manual/images/img-<N>-visual.md`：

```markdown
# 图片 #N 视觉信息
图片类型：立绘/设定图
提取时间：[日期]

---

## 外貌描述
[描述外貌、服装、气质]

## 文字说明（如有）
[图片中的文字内容]
```

### 类型 C：漫画分镜 / 连续截图

用户可能一次上传多张连续的截图（漫画分镜、连续对话）。

1. 按上传顺序处理，不乱序
2. 先告诉用户你理解的顺序：「我会按图1→图2→图3的顺序处理，对吗？」
3. 将连续截图作为一个场景处理，写入同一个文件

## 图片处理注意事项

**告知用户的提示**（在引导时说一次）：

```
注意：
- 图片越清晰，提取越准确
- 从图片提取的文字我会标注「来自图片」，和确定的文字材料区分
- 角色立绘这类图片，我会描述视觉特征，写进外貌部分，不混入台词
```

**内部处理原则**：
- 图片提取的内容可信度低于直接粘贴的文字
- 提取不确定的内容，在 persona.md 里用「(据图片推测)」标注
- 设定图的外貌信息 → 写进 persona.md 的外貌部分
- 设定图的能力/技能信息 → 写进 world.md 的能力部分
- **不要**把立绘的视觉描述混入台词或性格提炼

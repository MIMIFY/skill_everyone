# 材料合并策略

Phase 1.5 时读取此文件。同时有自动调研结果和手工材料时执行。

---

## 合并原则

1. **手工材料权重 > 自动调研**：用户提供的视为更可信的一手来源
2. **矛盾时两者都保留**：不强制统一，标注来源，让提炼阶段自己处理
3. **不重复**：相同信息（比如同一句台词出现两次）只保留一次，优先用原文版本

---

## 执行步骤

### 1. 读取所有材料

```
CHAR_DIR="$SKILL_DIR/characters/<slug>"

自动调研：$CHAR_DIR/references/auto/wiki.md
          $CHAR_DIR/references/auto/quotes.md
          $CHAR_DIR/references/auto/analysis.md

手工文字：$CHAR_DIR/references/manual/text/*.md（跳过 source-path.txt）
手工图片：$CHAR_DIR/references/manual/images/img-*-text.md
          $CHAR_DIR/references/manual/images/img-*-visual.md
```

### 2. 分类整理

将所有材料按信息类型归类：

| 类型 | 合并到 |
|------|--------|
| 基础背景/简介 | `merged.md` → 背景部分 |
| 台词/直接引语 | `merged.md` → 台词部分 |
| 行为场景 | `merged.md` → 行为部分 |
| 外貌视觉 | `merged.md` → 外貌部分 |
| 社区分析/解读 | `merged.md` → 解读部分 |

### 3. 冲突处理

遇到同一信息点有出入时：

```markdown
## [信息点]

自动调研：[自动调研的描述]
手工材料：[用户提供的描述]
→ 处理：保留两者，提炼时以手工材料为主
```

### 4. 写入 merged.md（路径：$CHAR_DIR/references/merged.md）

格式：

```markdown
# [角色名] 合并材料
合并时间：[日期]
材料来源：[列出使用了哪些文件]

---

## 背景与基本信息

[整合的背景信息，标注来源：(自动) / (手工) / (图片)]

## 台词记录

> "[台词]"
来源：[章节/场景] (来源类型)

> "[台词]"
...

## 关键行为场景

### [场景名]
[场景描述]
来源：[描述来源]

## 外貌与视觉
[外貌信息，仅来自设定图/立绘的标注"(图片推测)"]

## 社区解读与分析
[分析内容]

## 冲突记录（如有）
[记录有出入的信息点]
```

---

## 合并完成提示

不需要展示给用户，直接进入 Phase 2 提炼。
只有当发现重要冲突（不是细节出入，而是人设层面的矛盾）时才询问用户：

```
我注意到材料里有个出入：

自动调研说：[描述A]
你提供的材料说：[描述B]

提炼时用哪个版本？
  [1] 用我提供的材料
  [2] 用自动调研结果
  [3] 两个都保留，在 Skill 里标注这个差异
```

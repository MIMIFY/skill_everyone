# 手工文字材料采集协议

Phase 1 路径 2 时读取此文件。引导用户提供文字材料。

---

## 引导提示

向用户展示：

```
好，你来提供材料。

可以粘贴：
- 原著片段（小说章节、剧本台词、游戏文本）
- 对角色的描述（作者原话、百科介绍）
- 你自己对这个角色的理解和描述
- 角色的具体行为记录（某个场景里发生了什么）

每粘贴一段，告诉我这是什么（例：「第五章对话」「wiki 介绍」「自己总结」）。
可以分多次粘贴，粘完了输入「完成」。
```

---

## 接收材料的流程

### 每接收一段材料

1. 询问来源标注（如果用户没说）：
   ```
   这段材料来自哪里？（一句话就行，比如「第三章」「角色台词」「自己描述」）
   ```

2. **立即用 Write 工具写入文件**（必须执行，不能跳过）：

   **A. source 备份**（原始材料存档，不参与 Phase 2 提炼）：
   - 路径：`$SKILL_DIR/characters/<slug>/references/manual/source/text-<N>-raw.md`
   - 格式：用户粘贴的原文，不做任何加工，只加一行头：
     ```markdown
     # 原始材料 #N（备份）
     来源：[用户说的来源]
     备份时间：[日期]
     
     ---
     
     [用户粘贴的原文，一字不改]
     ```

   **B. 处理文件**（Phase 2 实际读取的）：
   - 完整路径：`$SKILL_DIR/characters/<slug>/references/manual/text/01.md`（`<slug>` 替换为本角色实际 slug）
   - 按输入顺序命名：`01.md`、`02.md`...
   - 格式：
     ```markdown
     # 材料 #N
     来源：[用户说的来源]
     类型：[原著文本 / 台词 / 百科 / 用户描述]
     
     ---
     
     [用户粘贴的内容原文]
     ```
   
   **如果用户提供的是文件路径（.txt / .md 等）**：
   
   先用 Bash 检查文件行数：
   ```bash
   wc -l "<文件路径>"
   ```
   
   - **行数 ≤ 300 行**：
     1. 用 Read 工具读取全文
     2. 写入 source 备份：`references/manual/source/text-<N>-raw.md`（同上格式，内容为全文）
     3. 写入处理文件：`references/manual/text/01.md`（同上格式）
   
   - **行数 > 300 行（长篇小说、完整剧本等）**：
     1. **source 备份只记录路径**，写入 `$SKILL_DIR/characters/<slug>/references/manual/source/text-<N>-path.txt`：
        ```
        原始文件路径：<文件路径>
        行数：<N> 行
        备份时间：[日期]
        说明：文件过大，source 只保留路径引用。如需重新提炼，用 Read 工具读取指定行范围。
        ```
     2. 处理文件同旧逻辑：保存路径引用到 `references/manual/text/source-path.txt`，用 grep 提取关键段落写入摘录文件
     3. 告知用户：「文件较长（N 行），已提取 [角色名] 相关片段保存为摘录文件，原文路径已记录在 source 备份目录。」

3. 确认收到：「收到，继续粘贴下一段，或输入"完成"。」

### 用户输入「完成」后

汇总：

```
收到 X 段材料：
  01. [来源标注] —— [前20字]...
  02. [来源标注] —— [前20字]...
  ...

开始提炼吗？（回复"好的"继续）
```

## 材料类型识别

接收到材料后，在内部标注类型，影响后续提炼时的权重：

| 类型 | 判断依据 | 提炼权重 |
|------|---------|---------|
| 原著文本 | 明显是书/剧本/游戏原文风格 | 最高 |
| 台词 | 直接引语形式 | 最高 |
| 百科/介绍 | 第三人称描述风格 | 中 |
| 用户描述 | 用户自己总结的 | 中（主观，标注为用户视角） |

---

## 补充引导

如果用户说「我不知道粘什么」，给具体建议：

```
可以这样：

1. 找这个角色出场最多的几个章节/场景，截几段对话粘进来
2. 把角色做过的几个重要决定用自己的话描述一下
3. 说说这个角色给你留下最深印象的一面是什么

哪怕只有几段，也比没有好。
```

如果用户说「我只记得大概，记不住原文」：

```
没关系，用你自己的话描述就行。
说清楚：他/她是什么样的人、怎么说话、遇到事情会怎么反应。
你的描述会作为"用户视角"材料，在生成 Skill 时会标注来源。
```
